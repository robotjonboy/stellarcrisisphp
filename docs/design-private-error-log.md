# Design: Private Error Log (Admin-Only)

## Problem

Production debugging relies on an HTML error log written by `debug.php` (`cjp_error_log`). Today that file is:

1. **Hardcoded** as `errorlog.html` in the application directory (the HTTP document root).
2. **World-reachable** — Apache serves it as a static file with no authentication. Admin “View Errors” is only a link to that URL.
3. **Over-permissive on disk** — historically mode `666`, so any local user can read or poison it.

Anyone who learns `/errorlog.html` (or the Docker AIO symlink to `/data/logs/errorlog.html`) can read stack traces, SQL text, paths, and other secrets from failed requests.

Constraints:

- Operators still want a **file-based** log that is easy to browse in prod (not email-only, not a DB table).
- Shared hosting and Docker AIO must both work.
- Auth remains form POST + `$authenticated_as_admin` (no new cookie session for this feature).

## Goal

Keep the same HTML append log, but:

1. Store it at a path **outside the web document root** (or otherwise not HTTP-mapped).
2. Make **Administration → View Errors** the only supported way to read it in the browser (after admin auth).
3. Document how shared-hosting operators set path and filesystem permissions.
4. Stop Docker from exposing the log via a docroot symlink.

## Non-goals

- Do not move logging to the database in this change.
- Do not add log rotation/purge UI (operators may truncate the file manually).
- Do not change what is logged (still HTML reports with backtraces).
- Do not require PHP `$_SESSION`.

## Design

### Config

Reuse existing keys in `serverconfig.php`:

| Key | Meaning |
|-----|---------|
| `error_log_type` | `file` (unchanged) or `email` |
| `error_log_path` | **Absolute** filesystem path to the log file (preferred), or a path relative to the app directory |

Examples:

- Shared hosting: `/home/USER/private/sc-logs/errorlog.html`
- Docker AIO: `/data/logs/errorlog.html` (already generated by `docker/render-config.php`)

Relative paths resolve against the app directory (where `debug.php` lives). Relative paths that fall **inside** the app tree remain writable for backwards compatibility but are treated as **misconfigured** (admin viewer shows a warning). Operators must move the file outside the docroot.

### Write path

`reportError()` / `cjp_error_log()` write to `sc_error_log_path()` instead of a hardcoded `errorlog.html`.

On successful create/append, best-effort `chmod` to `0640` so new files are not world-readable.

### Read path (admin only)

`viewErrors()` (admin menu) no longer emits `<a href="errorlog.html">`. After the existing `$authenticated_as_admin` gate in `adminAction()`:

1. Resolve `error_log_path`.
2. If missing/unreadable, show a short HTML message.
3. Otherwise stream the file with `Content-Type: text/html` (entries are already HTML), `Cache-Control: no-store`, and `X-Content-Type-Options: nosniff`.
4. Do **not** accept the path from request parameters.

### HTTP denial (defense in depth)

Even after the file leaves the docroot, deny accidental leftovers:

- Docker vhost: deny `errorlog.html` (and stop creating `$APP/errorlog.html` → `/data/logs/...` symlink).
- Shared hosting: document an `.htaccess` / panel rule denying `errorlog.html` if a stale copy remains under `public_html`.

### Permissions (filesystem)

| Environment | Owner | Dir mode | File mode |
|-------------|-------|----------|-----------|
| Shared hosting | PHP/Apache user (often the account user) | `750` on private log dir | `640` on the log file |
| Docker AIO | `www-data:www-data` | `750` on `/data/logs` | `640` on `errorlog.html` |

Every directory on the path must be executable (`x`) by the PHP user so it can traverse to the file. The file must **not** live under the vhost `DocumentRoot` unless HTTP deny is guaranteed (still discouraged).

## Threat notes

| Threat | Mitigated? |
|--------|------------|
| Anonymous `GET /errorlog.html` | Yes, if file is outside docroot and/or denied; admin UI requires admin auth |
| World-readable `666` log | Yes, target `640` |
| Path traversal via POST | N/A — path only from server config |
| Compromised admin account | Can still read the log (acceptable; same as other admin tools) |
| SQL/connect failure while logging | Unchanged — file append does not need MySQL |

## Testing checklist

- [ ] Set `error_log_path` to a private absolute path; trigger a warning; file grows; mode is not world-writable.
- [ ] `GET` of old `/errorlog.html` URL is 404 or 403.
- [ ] Non-admin cannot reach View Errors (existing admin gate).
- [ ] Admin View Errors shows the log contents in-browser.
- [ ] Docker: no symlink under `/var/www/sc/errorlog.html`; log only at `/data/logs/errorlog.html`.
- [ ] Shared hosting doc followed on a fresh private directory works end-to-end.

## Rollout

1. Deploy code that honors `error_log_path` and admin viewer.
2. Create private directory; move or recreate the log; set ownership/modes (see `docs/shared-hosting-error-log.md`).
3. Update `serverconfig.php` `error_log_path`.
4. Remove webroot `errorlog.html` / Docker symlink; confirm HTTP deny.
5. Verify Admin → View Errors.

## Summary

| Before | After |
|--------|-------|
| `errorlog.html` in docroot | Path from `error_log_path`, outside docroot |
| Public static URL | Admin-only PHP stream |
| Docker symlink into app tree | Log stays under `/data/logs` only |
| Mode often `666` | Target `640` / dir `750` |
